# Design: packet/v2 and the 0.6 contract train

## Problem Statement

PacketcraftR has two versioned contracts. `packetcraftr.packet/v1` tags every
value (`{"type":"unsigned","value":64}`), so a four-layer packet is ~90 lines
and duplicates information the codec registry already holds (field kind,
required, derived). `packetcraftr.output/v1` is 145 `$defs` because each of
21 commands has its own envelope body. `TODOS.md` already queues a "0.6
output-contract break". The ask: design the v2 schemas and the change that
makes this an expert-grade library and CLI.

Decision from the session: **the packet document is the product.** The
library-API freeze and the output-envelope unification are supporting scope.

## What Makes This Cool

One document, many verbs. A fixture author writes:

```yaml
schema: packetcraftr.packet/v2
layers:
  - ethernet: {destination: 02:00:00:00:00:02, source: 02:00:00:00:00:01}
  - ipv4:
      identification: 4660
      dont_fragment: true
      ttl: 64
      source: 192.0.2.1
      destination: 192.0.2.2
  - udp: {source_port: 49152, destination_port: 9}
  - raw: {bytes: 0x68656c6c6f}
```

and the same file drives `build`, `fuzz`, `replay`, `exchange`, templates,
and CI fixtures. `dissect` emits the same shape back, minimized, so
`dissect → edit one field → build` reproduces bytes exactly. A negative test
is one literal on a derived field (`checksum: 0xdead`) under
`--mode permissive`.

Why this beats the field: Wireshark's `json2pcap` round-trips *byte
positions* and breaks under reassembly and endianness ambiguity. Ostinato
describes packets in protobuf with computed, overridable fields, and scapy's
`IP(ttl=64)/UDP(dport=53)` carries the same protocol+field identity in
Python. A document keyed by `protocol + field name` round-trips *meaning*,
and terseness falls out for free. What none of them ship is a data-only,
schema-validated file generated from the codec registry that round-trips
bytes exactly; that is the claim this design makes.

## Constraints

- Rust 2024 workspace, MSRV pinned; `indexing_slicing` and
  `arithmetic_side_effects` denied in library code.
- v1 contract is byte-stable through 0.5. 0.6 is the one deliberate break.
- Examples and tests stay on documentation address ranges and loopback.
- AGPL, `publish = false`; releases are per-target archives from
  `release.yml`.
- Primary reader of the format: the fixture author (protocol test suites,
  interop labs). Shell users keep the expression syntax; programmatic
  producers get one canonical encoding per kind.

## Premises (agreed)

1. **The registry is the schema.** `protocol + field name → FieldKind` is
   the source of truth for value parsing. The JSON Schema is generated from
   the registry (`packetcraftr schema emit --contract packet/v2`), never
   hand-edited, and enumerates real field names per protocol.
2. **Three omission tiers, all printable from the registry** (revised after
   the second opinion). Mapping from today's `derived`/`required` bools:
   `required=true` → required; `derived=true` → derived (a field marked
   both is derived: the value is computed, and `required` was only ever
   asserting presence in the reflective table); neither → optional.
   - *required*: omitted = error.
   - *derived*: omitted = `auto`, computed from the whole packet, including
     cross-layer rules. Explicit `auto` is allowed only here. `--mode
     permissive` lets a derived field carry a literal.
   - *optional*: omitted = a constant the registry carries as `default` and
     the schema prints.
   Fields whose value is a rule rather than a constant (`ipv4.protocol`,
   `ethernet.ether_type`, `udp.checksum` which is optional over IPv4 and
   mandatory over IPv6) are reclassified as derived. `layer/reflection.rs`
   gains a `default` slot.
3. **`dissect` emits the same v2 document, minimized.** "Minimized" means
   exactly one thing: a derived field is omitted when its observed value
   equals what `auto` would compute for that packet. A derived field whose
   observed value differs (a wrong checksum in a real capture) is always
   emitted as a literal, and such a document builds only under permissive
   mode; that is what keeps the corpus round trip byte-identical. Optional
   fields are always emitted, so output never depends on a default
   changing. `--full` emits every field, derived included.
4. **One bump, one release.** 0.6 = packet/v2 + output/v2 + the TODOS
   renames. v1 documents stay readable with a deprecation warning and a
   `convert` command; v1 output is not kept.
5. **Distribution is deferred, not absent.** Release archives already ship;
   Homebrew, `cargo binstall`, man pages, and the crates.io publish wait.

## Cross-Model Perspective

Independent Opus 5 cold read, summarized:

- Coolest unconsidered version: the document as a *diff target*. Semantic
  `diff` by field identity (`ipv4.ttl: 64 → 63`, `+ vlan[1]`), a `--set
  ipv4.ttl=63` patch that applies to any document, and `test cases/*.yaml`
  with expected bytes. Nobody in this space has a semantic packet diff.
- What excites the user, quoted: "Same document drives build, fuzz, replay,
  exchange, and test fixtures." Settle design questions by "does this keep
  one document usable by all five verbs."
- Existing OSS for ~50%: `schemars` for `$defs` emission, `jsonschema` for
  in-process validation, `insta` for golden fixtures. The other 50%: the
  registry→schema emitter, the `FieldKind`-driven coercion layer, the
  minimizer.
- Challenged premise 2 (accepted, see revision above). Also flagged:
  list-valued fields (TCP options, IPv6 extension headers) need a place in a
  single-key layer map; repeated protocols need positional identity
  (`ipv4[1]`) in any path grammar from day one.
- Suggested first slice: `document/v2/{value,parse,emit}.rs`, then the
  corpus round-trip test, then `convert`, then the schema emitter. Leave
  output/v2 for last. (The reviewer's effort note applies: this first slice
  is days; the whole train is weeks.)

## Approaches Considered

### Approach A: Round-trip first, schema last (chosen)
New `document::v2` module (coerce by `FieldKind`, `Auto` as a parse result,
minimizing emitter); a corpus round-trip test over every registry protocol;
`convert`; schema generated from the registry; output/v2 and renames as the
final mechanical PRs. Effort L, risk Med. Reuses `document::{Packet,Layer}`,
`FieldValue`/`FieldKind`, the MAC/IP/hex parsers in `expression.rs`,
`Template`, and `published_example_matrix`.

### Approach B: Registry-driven contract for packet AND output
Extend reflection with default/tier and generate both schemas; define shared
output record types (frame, stream, finding, session) once. Effort XL, risk
High. Ruled out: the output unification is undesigned and would hold the
packet work hostage; the TODOS renames are the settled spec for output/v2 in
0.6, and record sharing is 0.7 scope.

### Approach C: Document as the primitive
A plus a path grammar shared by `--columns`, filters, `--set`, `diff`, and a
`test` runner. Effort XL, risk Med. Ruled out for 0.6 as too wide a surface
to freeze at once; the path grammar is designed in now and `diff`/`test`/
`--set` follow in 0.7.

## Recommended Approach

A, with C's path grammar reserved. Concrete design points:

**Value text forms (one per `FieldKind`, documented in the schema):**
`bool` → YAML/JSON bool; `unsigned`/`signed` → integer, `0x` hex string
allowed; `text` → string; `bytes` → `0x…` hex string (`0x` alone is empty)
or `{text: …}` for a UTF-8 literal; `ipv4`/`ipv6` → address string; `mac` →
colon or dash form; `list` → array of the element kind. `auto` is the bare
string `auto`, accepted only on derived fields.

**Layer shape:** a layer is a single-key map `{<protocol or alias>: {fields}}`.
Protocol aliases are accepted on input; emission always uses the canonical
name. Field aliases (today consumed only by getter/setter dispatch in
`reflective_layer!`) get an `aliases` slot on `FieldSchema` so the schema
can list them; emission uses the canonical field name.

**Core model changes this requires:** `FieldKind::List` carries no element
kind today (the payload lives on `FieldValue::List(Vec<FieldValue>)`).
`FieldSchema` gains `element: Option<FieldKind>`; every `kind: List` field
in the tree is a homogeneous scalar list (`ipv6/srh.rs:60` segments of
ipv6, `dns.rs:296-298` names and codes), so lists stay scalar-homogeneous
in v2 and a structured-element form is a 0.7 TODO (eng review issue 3).

**Scalar coercion (eng review issue 5):** one `field::coerce(kind, &str)`
in core parses every text form. `document/v2` and `expression.rs` both call
it; the expression parser resolves the layer schema before parsing values,
so `raw(text=true)` is the text `true` and `udp(dport=0x35)` is 53. This
changes expression results for kind-mismatched inputs and is part of the
0.6 break; the existing expression tests are re-pinned.

**Registry defaults (eng review issue 6):** `FieldSchema.default` is
`Option<&'static str>` in v2 text form (`"64"`, `"false"`). A test coerces
every declared default and compares it to `Layer::default()`'s reflected
value, so the table cannot drift from the constructor.

**Minimizer (eng review issue 4):** the builder is the oracle. To emit a
decoded packet, set every derived field to `Auto`, build in strict mode,
and compare bytes to the frame. Equal: emit without derived fields.
Unequal, or build failed (decode-only layer, malformed, truncated): emit
every derived field as a literal (`Exact` as a scalar, `Raw` as `{raw:}`).
All-or-nothing per packet; per-field precision is a TODO. `--full` skips
the rebuild entirely.

**Path syntax (eng review issue 1):** reuse the filter engine's paths
unchanged. `filter/path.rs` already resolves `protocol.field` against the
registry and carries a 1-based layer occurrence as `protocol#N.field`
(`ipv4#2.ttl`, `vlan#2.id`); `#1` is implied. `--columns`, `--output
document` selection, and the 0.7 `--set` all consume `filter::path`; no
second resolver or grammar exists. An index on a non-list field or a path
that does not resolve is `request.unknown_path`.

**Permissive mode** stays what it is today: a per-invocation flag
(`--mode permissive` on `build`, and on every command that consumes a
document), never a field in the document. The document itself is
mode-neutral. A literal on a derived field is an assertion: strict mode
builds it when it matches what `auto` would compute (`ipv4.rs:166-171`,
`ValueExpectation::Required`) and fails with the existing build mismatch
error when it does not; permissive mode emits the literal as given
(eng review issue 7).

**Raw bytes on a derived field (eng review issue 2):** a bare scalar on a
derived field coerces by kind to `WireValue::Exact`; the single-key map
`{raw: 0x...}` sets `WireValue::Raw`, which permissive mode emits verbatim
regardless of length. `dissect` emits `{raw: ...}` whenever decode produced
`Raw`, so malformed frames round-trip.

**Emission rules:** `dissect` and `read --output document` emit minimized
v2 as bare YAML; multi-frame output is a stream of `---`-separated documents,
never a buffered array. JSON consumers read `.result.packet` from
`--output json|ndjson`, which is a v2 document under output/v2. `--full`
includes every field and skips the rebuild. Key order is registry order, not
alphabetical, so diffs are stable. The schema emitter uses the same
registry order so the generated file is deterministic and the CI drift
check is meaningful.

**Diagnostic codes added by v2** (codes are part of the frozen contract):

| Code | Exit | When |
| --- | --- | --- |
| `document.deprecated_schema` | 0 (warning) | v1 document read |
| `document.unknown_protocol` | 2 | layer key is not a protocol or alias |
| `document.unknown_field` | 2 | field key not in the protocol's schema |
| `document.value_form` | 2 | scalar does not parse as the field's kind |
| `document.auto_not_derived` | 2 | `auto` on a required or optional field |
| `document.missing_required` | 2 | required field omitted |
| `document.decode_only` | 2 | `build` given a decode-only protocol (`tls`, `dns`, `raw_ip`) |
| `document.unknown_schema` | 2 | `schema` key missing or not `packetcraftr.packet/v1\|v2` |
| `document.layer_shape` | 2 | a layer map has zero or more than one key |
| `document.duplicate_field` | 2 | the same field spelled by alias and canonical name in one layer |
| `request.unknown_path` | 2 | `--columns`/filter path does not resolve |
| (existing `packet.*` build mismatch, named in T3) | 3 | literal on a derived field differs from `auto` in strict mode |

Every `document.*` code is a request error (`Kind::Cli`, `request.*` after
T8) so it exits 2; the strict-mode mismatch is a packet error and exits 3
(`errors.rs:109`). Every message carries the field path (`proto#N.field`),
the offending text, the expected form, and the remedy; a table test per code
pins that shape (autoplan, DX).

`convert` is a CLI command under `commands/convert/`; the existing
`document/convert.rs` module (document ↔ model conversion) keeps its name,
and the v1→v2 rewrite lives in `document/v2/upgrade.rs`.

**Compatibility:** `schema: packetcraftr.packet/v1` is accepted everywhere
with a `document.deprecated_schema` diagnostic; `packetcraftr convert
[--to packet/v2] <file>` rewrites in place or to stdout.

**Output/v2:** apply the `TODOS.md` "0.6 output-contract break" list
verbatim (`cli.*`→`request.*`, durations as `*_ms`, flag renames, schema
descriptions). Every `result.packet` and `result.dissection.packet` becomes
a v2 document. No envelope restructuring in 0.6.

**CLI ergonomics (scope F), its own PR after the contract lands:**
`--columns <path,...>` on capture-reading commands using the path grammar;
`--output document` on `read` and `dissect`; `protocols <P>` prints tier,
default, aliases, and text form per field. Extending `--filter` to every
capture-reading command is unrelated to the break and moves to 0.7.

## Decisions taken during review

- Decode-only protocols (`tls`, `dns`, `raw_ip`) appear as readable layers
  in `dissect --output json`; `--output document` emits them as
  `raw: {bytes: ...}` so the document builds (autoplan, revising the earlier
  call: every field of those layers is `read_only`, so a `tls:` layer can
  never parse back). v2 parse is data-only and never dispatches `set_field`;
  a hand-written `tls:` layer fails at model conversion with
  `document.decode_only`. The schema marks them `decode_only: true`.
- Bytes are hex-only in v2 (`0x…`). The `{text: …}` spelling is dropped;
  `raw` keeps its `text=` expression sugar, which the expression parser
  already turns into bytes.
- YAML scalars are parsed as untyped strings first and coerced by
  `FieldKind`, so `0x10`, `010`, and `1e3` mean what the fixture author
  wrote, not what YAML 1.1 guesses. Integers in JSON are accepted directly.

## Success Criteria

- Corpus round-trip test: `bytes → dissect → v2 → build → bytes` is
  byte-identical for every builtin default wire image
  (`protocol_codec_matrix.rs:75` extended), every `examples/captures/*`
  frame, every `protocol_end_to_end` fixture, and seeded `fuzz`-mutated
  variants of each (mutated variants build under permissive).
- `read --output document` on the shipped capture stays within 3x of
  `--output ndjson` wall time (pinned by a generous timing test);
  `--full` skips the rebuild.
- `packet-ipv4-udp.json` rewritten in v2 is under 25 lines.
- `schemas/packetcraftr.packet.v2.schema.json` is generated; CI fails if the
  committed file differs from `schema emit`.
- Every example under `examples/documents/` validates against the v2
  schemas and matches CLI output byte for byte (existing matrix test).
- `protocols <P>` reports `tier` and `default` for every field, with no
  field whose omission behaviour is undocumented.
- All v1 example documents convert and build to the same bytes as before.
