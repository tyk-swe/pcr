# Bind live plans and engagement journals by digest

Differential Campaigns already require a live run to present the digest a plan-only run printed, which proves the operator reviewed the exact packets, budgets and target before anything was sent. Send, exchange, scan and replay had no equivalent, so a reviewed plan and the executed plan could drift apart through an edited flag, a changed capture file or a different Scope with nothing in the output to show it. Engagement records had the mirror problem, because result files were bound into an Evidence bundle by hash at report time but nothing ordered them into a tamper-evident sequence an operator could verify months later.

We therefore add an opt-in plan gate to send, exchange, scan and replay. A `--plan-only` run prepares the operation exactly as the live run would and prints a digest over what will be sent, and a live run presenting `--plan-digest` refuses to send unless its prepared plan reproduces that digest. Each command binds what it can prove at preparation time. Send and exchange hash every expanded packet as built before route address filling, together with scheduling, the destination override and a canonical Policy digest. Replay hashes every frame in the snapshotted capture with its timing, routing and filter arguments. Scan binds target declarations, endpoint selection, the requested and effective scan methods, scheduling, payload bytes and policy before resolution, so hostname answers are deliberately not pinned and can still change between planning and execution. Interface selection is not bound by any of these digests, matching the differential precedent. The gate stays opt-in for these commands because differential is the workflow whose Verdicts claim proof, while making two-phase review mandatory for every send would change long-standing one-shot behaviour for no evidence gain.

The engagement journal is a separate `packetcraftr.journal/v1` document built offline from finished aggregate results. Each record binds its command, the SHA-256 of the exact result file bytes, an optional Scope digest and plan digest, and the previous record digest, so editing, reordering or dropping a record breaks verification. Building from finished results instead of appending inside every live command keeps one writer, composes with the staged no-clobber publication rules, and never adds a second side effect to a live operation. `analyze report --journal` anchors the verified journal head in report measurements after requiring every input to appear in the journal, which carries the anchor into the Evidence bundle without a bundle v2. The chain is tamper-evident only once its head is anchored somewhere the operator does not solely control, and the docs say so rather than calling an unanchored journal proof.

The scan self-detection preview is a projection and is labelled as one. It compares the planned attempts, timeout and endpoint counts with the built-in beacon detector thresholds and states where no built-in detector covers a pattern, but it does not simulate responses, retransmissions or a sensor view. Running detectors over synthetic captures waits for labelled scenario generation, where ground truth exists to measure the detectors against instead of asserting coverage from arithmetic.
