# PacketcraftR consolidated static audit report

**Consolidated:** 2026-07-30
**Sources:** three independently generated static reports, originally stored as `1.txt`, `2.txt`, and `3.txt`
**Scope reported by the sources:** 13 workspace crates, 427 Rust files, approximately 102,000 Rust source lines, 1,032 test functions, 6 fuzz targets, and 77 explicit unsafe blocks
**Method:** editorial deduplication and cross-referencing of the three reports; this consolidation is not an independent source-code or runtime validation
**Validation limitation:** the source reports state that they did not compile the workspace or run its tests, Clippy, Miri, sanitizers, or platform-specific runtime checks. Treat every finding as a static-analysis claim until reproduced.

## How this report is organized

- `EC-*` identifiers are the 149-entry catalogue from the broad edge-case review.
- `SUP-*` identifiers capture findings that were absent from that catalogue or materially strengthen one of its entries.
- Source-report counts are not added together because many findings overlap and several use different severity models.
- Where the reports disagree about intended behavior, the disagreement is preserved under **Classification conflicts** instead of silently choosing the more severe label.

## Executive summary

The broad source report catalogued **149 edge cases**: **1 High**, **48 Medium**, **83 Low**, and **17 informational/documented compatibility edges**. The other two reports add **29 supplemental finding groups or material refinements**. Those 29 are not all additive: several deepen an existing `EC-*` entry, and two expose classification conflicts.

No obvious memory-unsafety exploit was found in the inspected native FFI. The strongest parts of the codebase are prospective accounting, checked integer arithmetic, bounded parser framing, sticky failure handling, explicit unsafe isolation, fuzz-target coverage, and deterministic evidence validation. The largest residual risks are semantic boundaries rather than unchecked indexing: authorization-to-execution drift, time/lifecycle regressions, cross-interface identity collisions, post-side-effect errors that look retryable, and standards-valid wire variants that are rejected or interpreted opaquely.

### Highest-priority conclusions

- **SUP-001 — PCAPNG metadata has no cumulative byte budget** (`High`, static claim). Up to roughly 64 GiB of metadata can be read under default block limits before the metadata-block count rejects the stream.
- **SUP-002 — Final external-codec output is not re-authorized** (`High`, static claim). A second build after route/policy validation can change a destination without a final policy check.
- **SUP-003 — Fragmented transport traffic is filtered before reassembly** (`High impact`, classification disputed). Transport filters cannot see fragment payloads represented as raw data, so fragmented TCP/UDP may never reach reassembly.
- **EC-005 / EC-013 / EC-022 — Stateful identities omit capture and encapsulation scope** (`Medium` in the broad catalogue, `High` in another report). Independent interfaces, VRFs, VLANs, or tunnels can be merged into one stream or datagram.

## Detailed P0/P1 findings

### EC-127: Execution is not cryptographically or structurally bound to the authorized built packet

**Severity / priority / confidence:** High / P0 / Confirmed
**Component / type:** live fuzz / Authorization-boundary defect
**Trigger:** A custom executor, changed ClientExecutor options, or future drift builds/sends bytes or a destination different from the prebuilt campaign.
**Impact:** Policy authorizes cloned prebuilt packets/destination, but validation only checks executor.built == executor.sent; unauthorized bytes/destination can cross the live boundary.
**Evidence:** `crates/packetcraftr-workflow/src/fuzz/engine.rs:69-130,163-181; crates/packetcraftr-workflow/src/fuzz/execution.rs:41-118; crates/packetcraftr-workflow/src/fuzz/adapter.rs:64-75`
**Recommended change:** Pass the exact authorized BuiltPacket and destination into execute, hash/compare exact bytes and route destination afterward, and remove duplicate external option sources.

### EC-001: An older caller timestamp moves an active datagram backward in time

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** fragment reassembly / Correctness defect
**Trigger:** Push any later fragment with now < the flow's previous last_update, then expire using a current timestamp.
**Impact:** The flow can expire earlier than it should even though newer traffic was already observed.
**Evidence:** `crates/packetcraftr-session/src/fragment.rs:265-276,334-342; TCP already clamps at crates/packetcraftr-session/src/tcp/pending/commit.rs:26-29,93`
**Recommended change:** Assign last_update = last_update.max(now), and add a non-monotonic timestamp regression test.

### EC-002: A complete one-fragment datagram is rejected by the retained-table aggregate budget

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** fragment reassembly / Accounting defect
**Trigger:** Fill aggregate retained state near max_aggregate_bytes, then push offset=0, MF=false for a new datagram.
**Impact:** A packet that retains no table state can fail AggregateByteLimit because accounting runs before the direct-complete fast path.
**Evidence:** `crates/packetcraftr-session/src/fragment.rs:238-263; crates/packetcraftr-session/src/fragment/accounting.rs:44-75`
**Recommended change:** Take the zero-retention completion fast path before aggregate retained-state accounting; still enforce per-flow/protocol packet size.

### EC-003: Non-final fragment payload length is not required to be an 8-byte multiple

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** fragment reassembly / Wire-semantics validation gap
**Trigger:** Call Reassembler::push directly with more_fragments=true and bytes.len() % 8 != 0.
**Impact:** Malformed IPv4/IPv6 fragment layouts can enter reassembly even though the built-in packet encoders refuse to create them.
**Evidence:** `crates/packetcraftr-session/src/fragment.rs:150-168; encoder checks in crates/packetcraftr-protocol/src/network/ipv4.rs:172-183 and crates/packetcraftr-protocol/src/ipv6/model.rs:355-367`
**Recommended change:** Reject a non-final fragment whose byte length is not divisible by eight, or explicitly document this API as protocol-agnostic.

### EC-005: Datagram identity omits interface, VRF, namespace, and tunnel context

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** fragment reassembly / Attribution defect
**Trigger:** Analyze fragments with the same addresses, identification, and next-header arriving on independent interfaces or overlapping network contexts.
**Impact:** Unrelated datagrams can collide, overlap, complete together, or evict each other.
**Evidence:** `crates/packetcraftr-session/src/fragment.rs:24-30; adapter construction crates/packetcraftr-analysis/src/session_index.rs:249-286`
**Recommended change:** Carry a caller-defined scope key (at least capture interface; ideally namespace/tunnel identity) into DatagramKey.

### EC-010: Traffic after a clean FIN can implicitly create a fresh generation

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** TCP reassembly / Lifecycle defect
**Trigger:** Reach the FIN byte so the direction is removed, then call push with a later ACK-only/control segment for the still half-closed connection.
**Impact:** The public reassembler can produce a spurious empty generation, later eviction evidence, or confusing state.
**Evidence:** `crates/packetcraftr-session/src/tcp/engine.rs:64-70; crates/packetcraftr-session/src/tcp/pending.rs:189-199; crates/packetcraftr-session/src/tcp/pending/commit.rs:60-68`
**Recommended change:** Require explicit open/SYN for an absent flow, retain a bounded closed-direction tombstone, or document and enforce caller-side control filtering.

### EC-013: Flow identity omits interface, namespace, VRF, and tunnel context

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** TCP reassembly / Attribution defect
**Trigger:** Feed identical four-tuples from independent capture interfaces or overlapping address spaces.
**Impact:** Unrelated TCP byte streams can be merged, conflict, reset, or evict one another.
**Evidence:** `crates/packetcraftr-session/src/tcp.rs:25-31`
**Recommended change:** Add a caller-provided scope discriminator to FlowKey and propagate it from analysis/live capture.

### EC-016: Instant overflow freezes capture time at the current value

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** analysis clock / Correctness defect
**Trigger:** A capture timestamp is so far after the first timestamp that base.checked_add(offset) returns None.
**Impact:** Expiry time stops advancing instead of saturating/failing, so stale reassembly state remains until final flush.
**Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:507-518`
**Recommended change:** Return a typed timestamp-range error or saturate to the latest representable Instant rather than falling back to base.

### EC-022: Conversation IDs omit interface and network-context scope

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** analysis stream index / Attribution defect
**Trigger:** The same endpoint tuple appears on two interfaces/VRFs/tunnels in one input.
**Impact:** Frames receive the same tcp.stream/udp.stream and are merged in stats/follow output.
**Evidence:** `crates/packetcraftr-analysis/src/session_index.rs:20-41,51-82`
**Recommended change:** Include capture interface and an optional caller scope in CanonicalFlow.

### EC-023: Positive pcap_activate warning statuses are treated as fatal errors

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** Npcap / Correctness defect
**Trigger:** Npcap activates successfully but returns a positive PCAP_WARNING_* status.
**Impact:** Capture is rejected even though the handle is usable.
**Evidence:** `crates/packetcraftr-net/src/platform/npcap/supported/handles.rs:121-130; only negative codes are modeled in supported/abi.rs:16-23`
**Recommended change:** Treat status >= 0 as activated, surface positive statuses as diagnostics, and reserve errors for negative values.

### EC-027: A backend error makes already queued frames permanently undrainable

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** live capture / Data-retention contract defect
**Trigger:** The worker enqueues frames, then records an error before the consumer drains them.
**Impact:** next_captured_frame returns the error before queue.pop_front, so exact evidence already captured is lost to the caller.
**Evidence:** `crates/packetcraftr-net/src/platform/live_capture/session.rs:113-136`
**Recommended change:** Choose and document a drain-then-error policy, or return a terminal error alongside the final queued batch.

### EC-028: Initial statistics support is mandatory for readiness

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** live capture / Compatibility defect
**Trigger:** A capture backend can deliver frames but its statistics call is unsupported or temporarily fails.
**Impact:** The worker exits before set_ready, making capture unusable for an ancillary feature.
**Evidence:** `crates/packetcraftr-net/src/platform/live_capture/worker.rs:21-36`
**Recommended change:** Treat unsupported statistics as zero/unknown with a diagnostic; reserve fatal errors for corrupt statistics contracts.

### EC-029: Final statistics failure converts a successful capture shutdown into failure

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** live capture / Post-success failure
**Trigger:** Frames were captured successfully, but source.statistics fails during shutdown.
**Impact:** The session reports an error after useful work and can cause higher layers to discard results or retry.
**Evidence:** `crates/packetcraftr-net/src/platform/live_capture/worker.rs:93-107; crates/packetcraftr-net/src/platform/live_capture/session.rs:150-170`
**Recommended change:** Return frames/results with a separate incomplete-statistics diagnostic or structured terminal status.

### EC-030: Receiver counter reset/backward movement becomes a near-2^32 drop delta

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** live capture / Accounting defect
**Trigger:** A backend resets a 32-bit drop counter, swaps handles, or reports a lower value for any non-wrap reason.
**Impact:** wrapping_sub records billions of dropped frames and can overflow aggregate statistics.
**Evidence:** `crates/packetcraftr-net/src/platform/live_capture/queue.rs:220-255`
**Recommended change:** Differentiate plausible wrap from reset; reset the baseline or mark statistics discontinuous.

### EC-031: Shutdown can block forever waiting for a nonresponsive worker

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** live capture / Liveness defect
**Trigger:** Backend interrupt does not wake next_event or the worker is stuck in a driver call.
**Impact:** shutdown joins without a timeout, hanging the caller/process.
**Evidence:** `crates/packetcraftr-net/src/platform/live_capture/session.rs:150-163`
**Recommended change:** Provide bounded shutdown, detach/quarantine a stuck worker, and return a typed timeout.

### EC-032: ECMP/multipath routing always chooses the first non-dead nexthop

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** Linux route / Route-selection mismatch
**Trigger:** Kernel returns RTA_MULTIPATH with multiple live weighted nexthops.
**Impact:** The chosen interface/gateway can differ from the kernel flow hash and actual packet route.
**Evidence:** `crates/packetcraftr-net/src/platform/linux/query.rs:64-85`
**Recommended change:** Honor weights and a deterministic flow hash, or ask the kernel with sufficient flow attributes and use its selected nexthop.

### EC-035: Route and interface queries have no operation timeout

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** Linux netlink / Liveness defect
**Trigger:** The netlink future or socket connection wedges and never resolves.
**Impact:** Both uncached thread join and cached worker response wait can block indefinitely.
**Evidence:** `crates/packetcraftr-net/src/platform/linux/worker.rs:108-133,146-237`
**Recommended change:** Wrap operations in a bounded runtime timeout and return a typed OS timeout; make shutdown bounded too.

### EC-045: IPv4 directed broadcasts are not recognized as Ethernet broadcast

**Severity / priority / confidence:** Medium / P1 / High
**Component / type:** route materialization / Correctness defect
**Trigger:** Send to a subnet-directed broadcast such as 192.0.2.255/24.
**Impact:** The planner may attempt ARP for the broadcast address and raw IPv4 only enables SO_BROADCAST for 255.255.255.255.
**Evidence:** `crates/packetcraftr-net/src/route/materialize.rs:232-252; crates/packetcraftr-net/src/platform/raw_ip/submission.rs:62-67`
**Recommended change:** Carry route prefix/broadcast metadata and map directed broadcast to ff:ff:ff:ff:ff:ff / SO_BROADCAST.

### EC-046: Native raw sends are synchronous and have no deadline/cancellation seam

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** raw IP / Liveness defect
**Trigger:** The OS send call blocks due to driver/network stack behavior.
**Impact:** Client/workflow deadlines cannot preempt it; a send or replay can hang indefinitely.
**Evidence:** `crates/packetcraftr-net/src/platform/raw_ip/submission.rs; client send/exchange only checks deadlines around provider calls`
**Recommended change:** Add OS-level send timeout/cancellation where available and an asynchronous/bounded provider contract.

### EC-052: Only the first resolved address matching packet family is routed

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** target resolution / Availability / selection defect
**Trigger:** A hostname returns multiple same-family addresses and the first is unroutable while a later one is usable.
**Impact:** The operation fails without trying an authorized fallback address.
**Evidence:** `crates/packetcraftr-client/src/target/contract.rs:133-142; crates/packetcraftr-client/src/lib.rs:267-276`
**Recommended change:** Attempt authorized addresses in resolver order with route fallback, bounded by the existing address limit.

### EC-055: Deadlines are cooperative around synchronous provider calls

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** client deadlines / Liveness defect
**Trigger:** Resolver, route, neighbor, capture, build extension, or I/O provider blocks beyond the deadline.
**Impact:** The operation can exceed max_duration indefinitely because checks run only before/after the call.
**Evidence:** `crates/packetcraftr-client/src/lib.rs:473-550,566-585; exchange transaction provider calls`
**Recommended change:** Use timeout-aware provider traits or run blocking providers behind cancellable bounded workers.

### EC-056: The one-packet send API has no timeout at all

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** client send / Liveness defect
**Trigger:** Any route, neighbor, build, or transmission provider hangs.
**Impact:** send() can block forever and has no caller-controlled deadline unlike exchange/workflows.
**Evidence:** `crates/packetcraftr-client/src/lib.rs:314-370`
**Recommended change:** Add SendOptions.timeout/deadline and thread it through every live provider.

### EC-060: A failure after transmission can discard all committed send evidence

**Severity / priority / confidence:** Medium / P1 / High
**Component / type:** exchange transaction / Transaction / retry hazard
**Trigger:** Transmission succeeds, then capture shutdown/statistics, decode, promotion, validation, or a post-call deadline check fails.
**Impact:** Caller receives Err with no structured committed-state record and may retry, duplicating packets.
**Evidence:** `crates/packetcraftr-client/src/exchange/transaction.rs and finalize paths; same pattern visible in replay engine`
**Recommended change:** Return an error type carrying sent frames/counts and a committed flag, or make post-send failures nonfatal diagnostics.

### EC-061: Capture statistics completeness can veto otherwise valid exchange results

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** exchange capture / Post-success failure
**Trigger:** Valid responses were captured but shutdown/final statistics fails.
**Impact:** The exchange fails and useful responses/sent evidence may be lost to the caller.
**Evidence:** `client exchange finalization plus crates/packetcraftr-net/src/platform/live_capture/worker.rs:93-107`
**Recommended change:** Separate data validity from statistics completeness and return partial/unknown statistics explicitly.

### EC-069: A learned neighbor is discarded if cleanup/statistics fails afterward

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** neighbor resolution / Post-success failure
**Trigger:** A matching ARP/NA was received, then capture shutdown or statistics validation fails.
**Impact:** The cache is not populated and retry emits more discovery traffic despite a valid answer.
**Evidence:** `crates/packetcraftr-net/src/neighbor/provider.rs:143-188`
**Recommended change:** Commit the neighbor before ancillary cleanup and return cleanup incompleteness as a diagnostic/partial status.

### EC-072: FCS metadata is discarded

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** PCAP/PCAPNG / Capture correctness / compatibility defect
**Trigger:** Read classic PCAP network-word FCS bits or PCAPNG if_fcslen.
**Impact:** Trailing FCS bytes can be interpreted as payload, checksum/dissection can be wrong, and transcoding loses metadata.
**Evidence:** `crates/packetcraftr-capture/src/pcap/classic.rs:41-51; Interface has no FCS field at pcap/models.rs:194-205; PCAPNG parser recognizes only tsresol/tsoffset`
**Recommended change:** Add per-interface FCS presence/length metadata and teach dissectors/transcoders whether captured bytes include it.

### EC-088: Valid Segment Routing Headers containing TLVs/padding are rejected

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** IPv6 SRH / Standards compatibility defect
**Trigger:** Decode an SRH whose Hdr Ext Len covers segment list plus TLVs/padding.
**Impact:** The decoder treats every byte after the fixed header as 16-byte segments and requires total remainder % 16 == 0; encoder cannot represent TLVs.
**Evidence:** `crates/packetcraftr-protocol/src/ipv6/model.rs:505-604,607-674`
**Recommended change:** Derive segment-list length from last_entry, parse/preserve a bounded TLV area, and validate Hdr Ext Len independently.

### EC-106: The same unsolicited frame can satisfy more than one probe

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** probe response selection / Attribution defect
**Trigger:** A weakly attributable reply matches multiple requests, especially repeated UDP/TCP attempts with coarse/equal timestamps.
**Impact:** One ambient packet can create multiple successes because unsolicited candidates are never consumed.
**Evidence:** `crates/packetcraftr-workflow/src/bounded_probe.rs:186-203`
**Recommended change:** Assign each exact frame to at most one probe using strongest correlation and deterministic global matching.

### EC-113: Bare RST sequence matching aliases all SYN probes whose ACK field is zero

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** TCP probe matcher / Response-correlation defect
**Trigger:** A bare RST with sequence 0 arrives for a tuple used by multiple SYN probes; requests use ACK=0 and differ only in sequence.
**Impact:** The response matches any such request despite not acknowledging its unique SYN sequence; stale/spoofed RST can satisfy the wrong probe.
**Evidence:** `crates/packetcraftr-protocol/src/matcher/reverse_flow.rs:77-123; traceroute SYN construction crates/packetcraftr-workflow/src/traceroute/engine.rs:271-302; tests accept bare RST at reverse_flow/tests.rs:145-163`
**Recommended change:** For bare RST, correlate against request sequence according to RFC reset generation rules plus IP identity/token, or avoid reusing the tuple concurrently.

### EC-119: A successful transmission can be reported as DurationLimit before evidence emission

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** replay / Transaction / retry hazard
**Trigger:** transmit succeeds and the deadline crosses during/just after the provider call.
**Impact:** Counters are committed internally, then enforce_deadline returns Err; caller may retry the same frame and duplicate wire traffic.
**Evidence:** `crates/packetcraftr-workflow/src/replay/engine.rs:208-243`
**Recommended change:** Return a committed transmission result with a terminal overrun flag, or check deadline only before irreversible send and report late completion as evidence.

### EC-120: Output callback failure occurs after wire transmission

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** replay / Transaction / retry hazard
**Trigger:** emit() fails due to serialization, broken pipe, or downstream sink error.
**Impact:** replay_capture returns Err after packet transmission; no summary carrying committed progress is returned.
**Evidence:** `crates/packetcraftr-workflow/src/replay/engine.rs:227-243`

### EC-121: Invalid provider evidence is detected only after the provider may have sent

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** replay / Transaction / provider-contract edge
**Trigger:** Backend transmits but reports wrong interface/byte counts/frame evidence.
**Impact:** The operation errors without a reliable committed marker although the external side effect already happened.
**Evidence:** `crates/packetcraftr-workflow/src/replay/engine.rs:208-225`

### EC-125: Any error discards the terminal summary for prior successful frames

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** replay / Partial-result loss

### EC-128: Prepared-case and evidence memory budgets are independent

**Severity / priority / confidence:** Medium / P1 / Confirmed
**Component / type:** live fuzz / Aggregate memory accounting defect

**Impact:** Total retained memory can approach roughly twice the advertised total, before clones/transients.
**Evidence:** `crates/packetcraftr-workflow/src/fuzz/mutation/preparation.rs:50-53,91-97,149-164; crates/packetcraftr-workflow/src/fuzz/execution.rs:159-217`

### EC-132: One executor failure discards structured results for earlier sent cases

## Supplemental findings and refinements

The following entries come from the other two reports. “New” means the broad `EC-*` catalogue has no equivalent entry; “expands” means the supplemental report identifies a materially broader mechanism or impact.

- **SUP-001 — PCAPNG metadata has no cumulative byte budget** (`High`, new). The reader permits 4,096 metadata blocks of up to 16 MiB each and reads a block body before incrementing/checking the block count. A hostile stream can therefore drive roughly 64 GiB of metadata I/O while higher-level frame-byte budgets remain untouched. **Evidence:** `crates/packetcraftr-capture/src/pcap/models.rs:12-19`; `crates/packetcraftr-capture/src/pcap/reader.rs:207-305`. **Action:** check declared block length against per-gap and operation-wide metadata-byte budgets before reading the body, and pass remaining operation budget into the reader.

- **SUP-002 — Final external-codec output is not re-authorized** (`High`, new). Destination policy is applied before route planning, but an external codec can participate in a second full build after MAC materialization. The final path checks length and permissive-build status, not the final destination. A stateful or defective trusted codec can therefore change route-bearing bytes after authorization. **Evidence:** `crates/packetcraftr-client/src/lib.rs:289-356,483-552`; `crates/packetcraftr-client/src/materialize.rs:192-204`; `crates/packetcraftr-packet/src/build/engine.rs:219-269`. **Action:** extract and authorize destinations after the final build, or build network bytes once and patch only a validated Ethernet field range.

- **SUP-003 — Transport filtering can prevent fragment reassembly entirely** (`High impact`, new mechanism; classification disputed). The display filter runs before fragment reassembly, while fragmented IPv4/IPv6 payloads remain `Raw`. A filter such as `tcp.port == 80` can reject every fragment before a TCP layer exists. **Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:245-253,426-435`; `crates/packetcraftr-protocol/src/network/ipv4.rs:329-363`; `crates/packetcraftr-protocol/src/ipv6/model.rs:431-448`. **Action:** feed bounded stateful analysis before display filtering, or add an explicit fragment-aware filtering phase.

- **SUP-004 — Release configuration pins a compiler version covered by a reported critical optimizer fix** (`High operational`, new, conditional). `rust-toolchain.toml` pins Rust 1.97.0, and one source report states that Rust 1.97.1 predates v0.4.0 and fixes a critical x86-64 miscompilation. The configuration is directly checkable; no PacketcraftR artifact corruption was demonstrated. **Evidence:** `rust-toolchain.toml:1-3`; `CHANGELOG.md:31`; `.github/workflows/release.yml:156-159`. **Action:** independently confirm the upstream advisory, pin at least 1.97.1 if applicable, and rebuild/reissue affected x86-64 artifacts from a clean target.

- **SUP-005 — Reassembly performs full-table expiry scans on pushable traffic** (`Medium`, new). Analysis calls TCP or fragment expiry before each push, and expiry scans the complete active table; fragment expiry also sorts collected keys. Crafted captures can force approximately `O(frames × active_flows)` work. **Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:273-278,426-434`; `crates/packetcraftr-session/src/tcp/engine.rs:122-132`; `crates/packetcraftr-session/src/fragment.rs:334-365`. **Action:** use an expiry heap/timing wheel or otherwise inspect only states whose deadlines are due.

- **SUP-006 — Response freshness starts before a blocking send commits** (`Medium`, new). Exchange records the freshness anchor before `io.send` returns. A matching frame observed during a slow provider call can later be treated as an unambiguous post-send response, while moving the anchor after return would incorrectly reject very fast legitimate replies. **Evidence:** `crates/packetcraftr-client/src/exchange/transaction.rs:210-227`; `crates/packetcraftr-client/src/exchange/accumulator.rs:166-175,488-498`. **Action:** have providers report a transmission interval or commit instant and classify in-call observations as ambiguous when no commit marker exists.

- **SUP-007 — Timestamp discontinuities can pin the analysis clock beyond the overflow case** (`Medium`, expands `EC-016`). A future first timestamp, a later forward outlier, or `Instant` overflow can cause subsequent timestamps to clamp to a stale maximum, delaying expiry and allowing unrelated state to coexist. **Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:474-529`. **Action:** define a typed discontinuity policy: reject, expire/re-anchor, or begin a new capture epoch.

- **SUP-008 — Simultaneous-open side state is not coupled to TCP lifecycle** (`Medium`, new). `half_open_pure_syns` is pruned only by later non-pure traffic in the same direction, not by flow expiry, eviction, close, reset, replacement, or flush. Historical keys can permanently consume its cap and disable protection for new flows. **Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:168-172,283-290,359`; TCP removal paths in `crates/packetcraftr-session/src/tcp/engine.rs`. **Action:** derive the decision from generation-aware reassembler state or prune the side table on every lifecycle event.

- **SUP-009 — Public Serde deserialization bypasses packet-document hardening** (`Low/Medium`, new). `PacketDocument`, `LayerDocument`, and recursive `FieldValue` shapes publicly derive `Deserialize`, while the stable byte, depth, layer, YAML, and structural limits live only in bounded parse constructors. Downstream generic deserialization can silently bypass those limits. **Evidence:** `crates/packetcraftr-packet/src/document/model.rs:31-44,147-218`; `crates/packetcraftr-packet/src/field/value.rs:59-77`. **Action:** remove direct checked-type deserialization, introduce an explicitly unchecked intermediate type, or implement bounded custom conversion.

- **SUP-010 — Workflow promotion deletes evidence in more cases than deadline expiry** (`High impact`, expands `EC-059`). Promotion transfers ownership out of `unsolicited`. On deadline expiry, missing freshness, or a frame observed before all requests become eligible, some or all candidates can be dropped instead of returned as ambient evidence. **Evidence:** `crates/packetcraftr-client/src/exchange/accumulator.rs:299-385`; `crates/packetcraftr-client/src/tests/promotion.rs:145-216,285-350`. **Action:** keep captured evidence append-only and store correlation as frame/request references plus eligibility metadata.

- **SUP-011 — Replay read-side budgets are bypassable and enforced after reads** (`High`, new). Selector-skipped frames bypass `max_bytes`, permitting about 156 GiB of payload reads under the stated defaults. Frame-count and per-frame-size checks also occur only after the reader has returned the complete frame. **Evidence:** `crates/packetcraftr-workflow/src/replay/engine.rs:65-138`; `crates/packetcraftr-workflow/src/replay/model.rs:90-105,175-194`. **Action:** charge every returned frame to a read-side counter and pass remaining count/size/byte budgets into the reader before body allocation.

- **SUP-012 — Stream IDs are allocated before filtering** (`Medium`, new). Every decoded flow enters the global stream map before the filter runs, so 8,192 irrelevant flows can exhaust `max_flows` before a targeted frame is reached. **Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:232-253`; `crates/packetcraftr-analysis/src/session_index.rs:62-82`. **Action:** separate global numbering from selected-flow limits, or make global indexing an explicit mode.

- **SUP-013 — Analysis frame and byte ceilings are post-read limits** (`Medium`, new). With `max_frames=N`, frame `N+1` is fully read before failure. A frame exceeding the total-byte limit and preceding PCAPNG metadata are likewise read before the analysis layer rejects them. **Evidence:** `crates/packetcraftr-analysis/src/pipeline.rs:185-219`; `crates/packetcraftr-capture/src/pcap/reader.rs:207-305`. **Action:** enforce remaining limits in the reader before record bodies are read.

- **SUP-014 — TCP history accounting does not reconcile actual `VecDeque` capacity** (`Medium`, new). Planning charges a requested capacity, then commit calls `VecDeque::with_capacity`; allocator/container rounding can reserve more than was charged. **Evidence:** `crates/packetcraftr-session/src/tcp/state.rs:56-62,98-105`; `crates/packetcraftr-session/src/tcp/pending/accounting.rs:67-80`. **Action:** use fallible exact reservation where possible and charge the actual resulting capacity.

- **SUP-015 — Live-capture `max_bytes` measures payload, not queue-resident memory** (`Medium`, new). Queue accounting omits frame structs, `Bytes` handles, deque slots/capacity, and metadata, so many tiny frames can consume several times the configured amount. **Evidence:** `crates/packetcraftr-net/src/capture.rs:21-24`; `crates/packetcraftr-net/src/platform/live_capture/queue.rs:86-94,200-214,261-269`. **Action:** rename the contract to payload bytes or conservatively charge fixed per-frame/container overhead.

- **SUP-016 — Response clones are not charged to a resident-memory budget** (`Medium`, expands `EC-106`). One unsolicited packet can be cloned into multiple response collections. Raw bytes may be shared, but decoded layer objects, layouts, diagnostics, and vector metadata are duplicated after the candidate was charged only once. **Evidence:** `crates/packetcraftr-client/src/exchange/accumulator.rs:314-350`; `crates/packetcraftr-client/src/exchange/contract.rs:21-59`; `crates/packetcraftr-packet/src/decode/engine.rs:72-79`. **Action:** store shared packet/frame references and budget response objects separately.

- **SUP-017 — Filter `!=` uses existential repeated-value semantics** (`Medium`, new but documented). For a multi-valued path such as `tcp.port`, `tcp.port != 80` is true when any value differs, so traffic with one endpoint on port 80 usually passes. **Evidence:** `crates/packetcraftr-packet/src/filter/eval.rs:119-163`. **Action:** define inequality as “no value equals,” or require explicit `any`/`all` syntax and warn on the ambiguous legacy form.

- **SUP-018 — Finalizing a built packet can create a second full-size copy** (`Medium`, new). When buffer slack remains, `into_bytes` copies the active slice while the original allocation is still alive, roughly doubling instantaneous packet memory. **Evidence:** `crates/packetcraftr-packet/src/build/engine/buffer.rs:95-142`. **Action:** split/freeze owned mutable bytes or document and budget the peak copy.

- **SUP-019 — Generic macOS struct serialization has an unproven unsafe contract** (`Medium confidence`, new). `structure_bytes<T>` exposes arbitrary C-struct object representations. Current concrete sockaddr types may contain no problematic padding, but the generic helper cannot guarantee all bytes are initialized or wire-safe for future callers. **Evidence:** `crates/packetcraftr-net/src/platform/macos.rs:431-471`. **Action:** serialize concrete fields explicitly or prove no-padding/POD invariants per concrete type.

- **SUP-020 — Neighbor evidence removal is quadratic** (`Low`, new). Repeated `Vec::remove(0)` shifts the remaining frame list and can produce `O(n²)` work. **Evidence:** `crates/packetcraftr-net/src/neighbor/provider.rs:451-484`. **Action:** use `VecDeque`.

- **SUP-021 — Filter evaluation allocates for full program length on every packet** (`Low`, new). The evaluator creates a boolean vector sized to the postfix program even though only maximum stack depth is needed. **Evidence:** `crates/packetcraftr-packet/src/filter/eval.rs:37-65`. **Action:** record maximum stack depth at compile time and reuse bounded scratch storage if profiling justifies it.

- **SUP-022 — Unknown string escapes silently remove the backslash** (`Low`, new). Expressions such as `"\q"` become `"q"` rather than failing or preserving the input. **Evidence:** `crates/packetcraftr-packet/src/expression/parser.rs:241-278`. **Action:** reject unknown escapes or preserve the backslash.

- **SUP-023 — `frame.time_epoch` collapses pre-1970 timestamps to zero** (`Low`, new). Genuine negative epoch timestamps become indistinguishable from UNIX epoch and from other timestamp-sentinel behavior. **Evidence:** `crates/packetcraftr-packet/src/filter/eval.rs:232-249`. **Action:** expose signed seconds or an optional/provenance-aware timestamp.

- **SUP-024 — Statistics offset conversion saturates at a `u64` nanosecond limit** (`Low`, new). The implementation saturates near 584 years even though `Duration` can represent a much larger seconds value. **Evidence:** `crates/packetcraftr-analysis/src/stats.rs:350-364`. **Action:** construct `Duration` from quotient/remainder seconds and nanoseconds.

- **SUP-025 — Non-exhaustive enum conversions defer schema drift to runtime panic** (`Low`, new). Wildcard `unreachable!` arms keep downstream code compiling when an upstream non-exhaustive enum gains a variant, then panic when that variant is converted. **Evidence:** `crates/packetcraftr-output/src/protocols/model.rs:70-86`; `crates/packetcraftr-output/src/replay/model.rs:42-52`. **Action:** use typed fallible conversion or an exhaustive helper in the defining crate.

- **SUP-026 — The nightly fuzz run has little job-time margin** (`Low operational`, new). A ten-minute campaign sits in a fifteen-minute job that must also update packages, install nightly and `cargo-fuzz`, build, and upload artifacts. **Evidence:** `.github/workflows/fuzz.yml:34-66`. **Action:** increase the job timeout or use a prepared image.

- **SUP-027 — Release dependency verification is Linux-specific** (`Low operational`, expands `EC-141` / `EC-149`). Release smoke uses `ldd` but has no equivalent `otool -L`, Windows import inspection, or functional native-backend initialization. **Evidence:** `.github/workflows/release.yml:229-236`. **Action:** add target-native dependency inspection and a privilege-free backend startup probe.

- **SUP-028 — `tcp.stream` has conflicting intended semantics across the reports** (`Design decision`, refinement of `EC-020`). The implementation permanently indexes a canonical four-tuple, while one report expects a connection-generation ID and another says endpoint-conversation semantics are deliberate. **Evidence:** `crates/packetcraftr-analysis/src/session_index.rs:20-82`; changelog/follow behavior cited by `EC-020`. **Action:** retain the current field only if it is explicitly named/documented as a conversation ID; add a separate generation-aware connection ID if Wireshark-style stream semantics are required.

- **SUP-029 — The `paste` advisory waiver is narrow and time-bounded** (`Informational`, governed exception rather than a defect). One report confirmed a documented exception for `RUSTSEC-2024-0436` with a reverse-dependency explanation, internal remediation target, and hard expiry. **Evidence:** `deny.toml:10-16`; `docs/security/RUSTSEC-2024-0436.md`. **Action:** keep the deadline and do not broaden or silently extend the waiver.

## Classification conflicts

1. **Connection identity:** `EC-020` treats four-tuple-wide `tcp.stream` as deliberate endpoint-conversation behavior; `SUP-028` records another report’s claim that users will reasonably read it as a per-connection generation. This needs an API/product decision, not a severity vote.
2. **Filtering before reassembly:** the broad report treats pre-reassembly filtering and resulting stream gaps as intentional (`EC-019`), while `SUP-003` shows that a transport filter may eliminate every fragment before transport fields exist. Even if the ordering is intentional, the fragmented-traffic consequence should be documented and regression-tested.
3. **Evidence deletion:** deadline-driven clearing is explicitly covered by tests (`EC-059`), while `SUP-010` classifies it as a high-impact evidence-preservation failure and identifies additional deletion paths. Intentional behavior can still violate the public forensic contract; ownership and API semantics should be reviewed together.

## Recommended remediation order

1. **Close authorization gaps:** bind live-fuzz execution to the exact authorized bytes/destination and re-authorize the external codec’s final built destination.
2. **Move limits before reads and allocations:** add cumulative PCAPNG metadata accounting, charge selector-skipped replay frames, and pass remaining analysis/replay limits into capture readers.
3. **Preserve committed work and evidence:** make captured evidence append-only and return committed-state/partial-result errors for replay, exchange, fuzz, and CLI output failures.
4. **Fix state identity and filtering contracts:** add interface/direction/encapsulation scope, decide whether stream IDs represent conversations or generations, and specify fragmented-traffic filter behavior.
5. **Repair clocks and lifecycle coupling:** keep fragment activity monotonic, define discontinuity epochs, and prune simultaneous-open state with TCP lifecycle events.
6. **Repair native correctness:** handle Npcap warnings, drain queues consistently, recognize counter resets, bound shutdown/netlink operations, and correct directed-broadcast routing.
7. **Make memory ceilings truthful:** account for empty flow metadata, actual container capacity, queue/container overhead, response clones, transient merge buffers, and packet-finalization copies; use fallible reservation on input-sized allocations.
8. **Tighten response correlation:** fix bare TCP RST matching, one-frame/one-probe assignment, and pre-send freshness ambiguity.
9. **Address wire compatibility:** support SRH TLVs, NDP extension chains, and capture FCS metadata, then prioritize option/tag parsing according to product scope.
10. **Harden release gates:** verify the compiler advisory, require CI for the exact tag SHA and branch ancestry, add target-native artifact probes, and publish signed provenance.

## Important non-defects / deliberate semantics

- Current changelog/tests treat `tcp.stream` as an endpoint-conversation identifier. `SUP-028` remains open because the field name can imply per-connection generations to downstream consumers.
- Workflow promotion clearing unsolicited evidence at the deadline is explicitly tested. `SUP-010` challenges the public contract and additional deletion paths, not whether the current test matches the implementation.
- Filters run before reassembly by design. `SUP-003` records the stronger consequence that transport-layer filters may reject every fragment before a transport layer exists.
- Exact send/replay intentionally avoids ordinary IP-stack fragmentation and supports only modeled media. These are compatibility/product-scope edges unless broader behavior is promised.
- Opaque IP/TCP/PPPoE/IPsec option payloads are memory-safe preservation choices. They become correctness issues only when callers interpret “decoded” as semantically validated.
- IPv6 jumbograms, GRE variants, VXLAN-GPE/GBP, generic ARP, and some non-Ethernet media are explicit support limitations, not hidden memory-safety bugs.

## Consolidation caveats

- The three inputs were LLM-generated static reports. This document merges their claims and evidence; it does not certify correctness or exploitability.
- The live-capture queue’s error-before-drain behavior is a data-retention/API policy issue, not a memory-corruption claim.
- The inspected Npcap FFI was reported to check null pointers, returned lengths, and structure bounds carefully. The identified Npcap defect concerns status-code semantics.
- Findings involving standards variants (SRH TLVs, NDP extension chains, FCS metadata) are source-confirmed implementation limitations; exact product severity depends on the compatibility guarantees you intend.
- Compile failures, test regressions, Miri/loom behavior, sanitizers, the reported compiler advisory, and actual platform runtime behavior remain unverified.
- No companion CSV was present in the workspace; this report is self-contained.
