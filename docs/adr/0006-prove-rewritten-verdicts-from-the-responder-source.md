# Prove rewritten Verdicts from the Responder source tuple

Differential Campaigns already prove accepted, unanswered, and flaky Verdicts with a cooperating Responder under ADR 0002. The Responder is an ordinary UDP socket, so it cannot see the IP header a middlebox forwarded and it cannot prove that a TTL, DSCP, or option field was rewritten in transit. It can see the source address and port each datagram arrived from, and reception records already carry that tuple next to the Canary identity.

We therefore add a rewritten Verdict only where that evidence is complete. A spoofed Campaign declares the exact source tuple it sends from, so when differential join finds a reception whose Variant, attempt sequence, and payload digest match an attempt but whose source tuple differs from the declared tuple, the packet provably arrived and provably did not arrive as sent. That attempt is rewritten rather than answered, and a Variant whose attempts were all received that way earns the rewritten Verdict. Unspoofed Campaigns record no sent source, because the route picks it, so a different reception source proves nothing for them and they never earn this Verdict from join.

IPv4 fragmentation joins the Catalog as two Variants, in order and reordered, using a zero UDP checksum so the fragments stay valid after the route fills the source in. Proving the destination of a fragment needs only its header destination, which every fragment carries, so IPv4 path semantics now read it for fragments as well. The IPv6 fragment guard stays, because IPv6 extension header order makes the same claim harder. IPv6 and TCP Intents are not added. The Responder speaks one IPv4 UDP Intent today, and each new Intent needs its own cooperating counterpart and reply correlation before any Verdict about it can be defended, which is the next decision to make rather than a Catalog edit.
