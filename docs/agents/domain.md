# Domain documentation

The four Rust crates in [the workspace](../../crates/) share one [glossary](../../GLOSSARY.md). Read it before exploring a crate and use its terms in issues, proposals, and tests. If a concept has no entry, check the usage in code before raising a glossary gap with the domain-modeling skill.

Read the [architecture decisions](../adr/) that apply to the area you are changing. If a proposal conflicts with a decision, cite the ADR and explain why it should be revisited.
