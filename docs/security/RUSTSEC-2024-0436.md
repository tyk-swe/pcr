# RUSTSEC-2024-0436 remediation

## Status

- Resolved: 2026-08-26
- Exception removed from `deny.toml`: 2026-08-26
- Owner: Native networking (`@tyk-swe`)

[`RUSTSEC-2024-0436`](https://rustsec.org/advisories/RUSTSEC-2024-0436.html)
is an informational advisory for the unmaintained `paste` crate. Between
2026-08-11 and 2026-08-26 PacketcraftR carried a dated `cargo deny` exception
for it, because `paste` was a build-time (proc-macro) dependency of
`netlink-packet-core 0.8`, reached through `rtnetlink 0.21` on the
`native-route` feature. It was never linked into the binary.

## Resolution

Upstream removed `paste` in `netlink-packet-core 0.9.0` (2026-08-18).
PacketcraftR moved to `rtnetlink 0.23`, which pulls `netlink-packet-core 0.9`,
`netlink-packet-route 0.33`, `netlink-proto 0.13`, and `netlink-sys 0.9`. The
same update dropped the last `thiserror 1.x` copy from the lock, so its
`[bans] skip` entries went too.

Checks run before removing the exception:

```console
cargo tree --locked --all-features -i paste      # "did not match any packages"
cargo check --locked --workspace --no-default-features
cargo check --locked -p packetcraftr-netio --no-default-features --features native-route
cargo check --locked --workspace --all-targets --all-features
cargo +1.96.0 check --locked --workspace --all-targets --all-features
cargo deny check
```

## If it comes back

A future dependency that reintroduces `paste` fails `cargo deny check` in CI.
Do not add an ignore without a dated remediation plan in this directory; the
`deny.toml` ignore has no automatic expiry, so the date has to be policed by
hand.
