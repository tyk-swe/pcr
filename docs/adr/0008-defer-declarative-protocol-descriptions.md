# Defer declarative protocol descriptions, and reject loadable protocol code

Adding a protocol today means writing a Rust codec and registering it with the built in catalog, which is the right amount of friction for protocols the tool ships and fuzzes. Low level work still meets private binary formats that will never be upstream protocols, so a data only description that could build and dissect simple fixed layouts without recompiling is attractive.

The description would be untrusted input in the same sense as a capture file, because operators share these documents during an engagement. It therefore needs the same treatment as the other bounded documents, meaning a versioned schema, hard limits on fields, lengths, and nesting, no expressions that can loop or allocate without bound, and fuzz targets before it can be called safe. It also has to join the registry without weakening the guarantee that unknown protocols cannot claim route bearing fields by naming them, which the live destination checks rely on. None of that infrastructure exists yet, and a half bounded version would be a parser for attacker controlled grammars inside a security tool.

Loadable plugins and embedded scripting are rejected outright. They would add unsafe loading or a new runtime dependency to crates that forbid unsafe code, and they would make the output of a run depend on code the evidence bundle cannot hash and reproduce. We therefore do not build declarative descriptions in this pass either. If the need returns, the smaller first step is a fixed layout description for dissection only, with no route bearing claims, its own schema and fuzz target, and build support considered only after dissection has survived real documents.
